## 2. Errors & Failures Encountered (Rework Required)
1. **ReferenceError on Undeclared Variable (`saved`):**
   - In `DecisionJournalScreen.tsx`, `if (!saved && isFounder)` was checked without `let saved = localStorage.getItem(key);`.
   - Result: Broke local storage loading immediately with a `ReferenceError`, swallowed by `try...catch`, leading to an empty decision list.
2. **Asynchronous Auth Race Condition at Mount:**
   - Client screen rendered synchronously and fired Firestore SDK calls at `t=0`.
   - Firebase Auth restores credentials asynchronously (300–800ms).
   - Result: Firestore SDK queries were sent unauthenticated (`request.auth == null`), failed with `permission-denied`, and left the journal empty.
3. **Unauthenticated REST Fallback:**
   - `firestoreSync.ts` fallback REST calls did not pass `Authorization: Bearer <idToken>`.
   - Result: Stricter Zero-Trust security rules returned 403 Forbidden on all REST queries.
4. **Fragile Identity Mapping (Single-Account Blindspot):**
   - Code strictly matched `email === 'guykul@gmail.com'`.
   - The founder logged in using his other verified Google Workspace account: `guy@kuleski.co.il` (UID: `B74F1e0OgnZx3JbcayLaigipBk33`).
   - Result: The system treated the founder as an unknown guest/user and blocked access to all founder decisions.
5. **Collection Fragmentation & String Inconsistency:**
   - In Firestore, legacy decisions were fragmented across `/users/Guy_Kuleski/decisions`, `/users/guy_kuleski/decisions`, `/users/guy kuleski/decisions` (space vs underscore), and `/decisions`.
   - Single-key queries missed documents stored under the alternative aliases.

## 3. Successful Resolution
- Declared and validated `saved` properly in `DecisionJournalScreen.tsx`.
- Implemented `waitForAuthReady` in `firestoreSync.ts` and auth state subscription in `DecisionJournalScreen.tsx`.
- Injected `Authorization: Bearer ${idToken}` into REST requests.
- Added comprehensive founder recognition for both Google accounts (`guy@kuleski.co.il`, `guykul@gmail.com`) and both UIDs in client and Firestore rules.
- Aggregated queries across all founder paths (`Guy_Kuleski`, `guy_kuleski`, `guy kuleski`, `guy_founder`) to retrieve all 55 unique decisions.
- Updated public bundled `DECISION_CYCLES.json` with all 55 decisions for robust offline availability.
