- **Category:** Architecture/Profile

## 1. What Failed / Rework Required
Mobile profile rendered empty because calculation was missing, and local DECISION_CYCLES.json was wiped by unauthenticated Firestore sync. User corrected initial approach of client-side computation, demanding that epistemic profile be computed, executed, and saved persistently on the backend server and only loaded to mobile on startup.

## 2. Root Cause Analysis & Solution
1. Implemented Server-Driven Profile generation in serve.js with DecisionProfileService and persisted to USER_PROFILES.json. 2. Added GET /api/user-profile and /api/user-profile/refresh endpoints. 3. Protected DECISION_CYCLES.json from being overwritten when Firestore returns 403 or 0 docs. 4. Improved quote/assumption extraction with HTML tag stripping. 5. Mobile client performs lightweight fetch on startup and caches profile in localStorage.

## 3. Persistent Lesson Learned
Complex epistemic profiles and heavy multi-decision aggregations must always be computed, executed, and persistently stored on the Backend Server as the single source of truth; client mobile apps must remain lightweight consumers that fetch pre-calculated models. Local cache files must never be overwritten with empty arrays upon API/network failures.
