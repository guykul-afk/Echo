# Echo Project Wiki

This is the persistent knowledge base for the Echo project. Lessons learned, rules, and patterns will be recorded here.

## 14/09/2026
* **Analyzing Historical Impact:** When asked to find "improvements made to the system" following a specific simulation or feature release, do not rely only on text inside the report markdown. The most accurate source of truth is the Git commit history (`git log`) right after the report was added.

## 16/09/2026
* **Server-Driven Epistemic Profile Architecture & Cache Protection:** Complex epistemic profiles and heavy multi-decision aggregations must always be computed, executed, and persistently stored on the Backend Server as the single source of truth; client mobile apps must remain lightweight consumers that fetch pre-calculated models. Local cache files must never be overwritten with empty arrays upon API/network failures. (Category: Architecture/Profile)
* **Stale Data Reliance:** Always query the source of truth (DECISION_CYCLES.json or the database) and explicitly sort by creation timestamp to find the latest record. Do not trust file names containing 'latest' or 'last' without verifying timestamps. (Category: Data Verification) - Execution Failures, Hardening & Identity Rework
* **Undeclared Variable in Try/Catch (Silent ReferenceError):** In JavaScript/TypeScript, never reference a variable before declaring it (e.g. `if (!saved)` without `let saved`). Even inside a `try/catch`, it throws a runtime `ReferenceError` that silently redirects control flow into the `catch` block, causing critical initialization logic (like loading saved decisions) to be skipped. Always run strict linter/type checks and write tests covering initial state loading.
* **Async Auth Readiness Race Condition:** In SPA frameworks with Firebase/Cognito/Supabase, auth state is restored asynchronously from local storage/IndexedDB (taking 300–800ms). Never issue authenticated cloud queries synchronously on initial component mount (`t=0`), because `auth.currentUser` is `null` and requests will silently fail with `permission-denied`. Always await auth readiness (e.g., via `waitForAuthReady` or `onAuthStateChanged`) or subscribe to auth state changes before dispatching data queries.
* **Bearer Tokens in REST Fallbacks:** When cloud security rules are tightened to Zero-Trust (`isAuthenticated()`), direct REST fallback calls using only API keys (`?key=${apiKey}`) will fail with HTTP 403. Any REST layer must explicitly inject `Authorization: Bearer ${idToken}` when a user session exists.
* **Multi-Account Founder Identity:** Never hardcode a single email string (e.g., `guykul@gmail.com`) for administrative/founder roles when the user operates across multiple verified accounts (e.g., Google Workspace `guy@kuleski.co.il` alongside personal Gmail). Always identify all verified account emails and UIDs, or map them through a canonical identity resolver.
* **Cross-Collection Alias Aggregation:** When legacy data exists across variations in naming conventions (e.g., `Guy_Kuleski`, `guy_kuleski`, `guy kuleski` with spaces, and root collections), querying only one variant causes data starvation and false "0 decisions" reports. Queries must aggregate across all known aliases and merge unique items by canonical ID.
